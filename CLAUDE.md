# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A JavaScript course exercise: a vanilla-JS (ES modules, no framework, no bundler) transaction browser styled with Tailwind CSS v4, reading from a json-server mock API. Domain vocabulary lives in `CONTEXT.md`: name things in code, tests and UI after its terms (Transaction, Reference ID, Amount, Owner, Direction, Summary, …). Decisions live in `docs/adr/`.

## Commands

```bash
npm install
npm run dev                     # json-server on http://localhost:3001 (also serves the repo root) + Tailwind watch
npm run seed                    # regenerate data/db.json deterministically (scripts/seed.js); overwrites any API writes
npm test                        # node:test unit tests in test/
node --test test/api.test.js    # a single test file
npm run css:build               # one-off minified Tailwind build
```

Open `http://localhost:3001/src/index.html`. json-server serves the page itself (`-s .`), so the API is same-origin (`API_BASE = ""` in `src/js/constants.js`; from any other port, e.g. Live Server on :5500, it falls back to `http://localhost:3001`) and the absolute `/assets/fonts/...` paths in `fonts.css` resolve.

Tests cover the pure modules (`api.js` param building and `summarize`, `format.js`, `state.js`, the seed); test names are behaviour sentences in domain language. The DOM code in `index.js` and `components/` has no tests: check it in the browser.

## API (json-server 0.17 — do not upgrade, see ADR 0001)

Resources: `users` (`id`, `name`, `phone`, `avatar` URL) and `transactions` (`id`, `refId` = Reference ID, `type`, `price` = Amount in Toman, `date` epoch-ms, `status` = `success|pending|failed`, `userId` = Owner). Writes through the API change `data/db.json` on disk.

All querying is server-side; `src/js/api.js` builds the params:

- Search box: digits only → `refId_like`, other text → `type_like` (regex-escaped); Persian/Arabic digits are normalized first.
- Filters: `type=`, `status=`, `userId=`. List adds `_sort`, `_order`, `_page`, `_limit=10`, `_expand=user`; total comes from `X-Total-Count`.
- Summary re-requests the same filters without paging and totals client-side (success only).

Direction is never stored: `directionOf(type)` in `constants.js` derives it from `TRANSACTION_TYPES`, and an unknown type counts as Out. Type values are the Persian labels in that list.

Seed data (`scripts/seed.js`) is fixed by a seed and an anchor date (2026-10-13): 8 owners, 80 transactions over the past year, Pending only in the last 3 days. Avatars are DiceBear URLs, so they need network; `Avatar` shows the owner's initial underneath and keeps it if the image fails.

## Front-end conventions

- Persian, right-to-left, Vazirmatn font (`assets/fonts/`). Amounts and counts show Persian digits with a Latin comma every three digits (`formatAmount`), rendered through `Digits`, which mutes the commas. Reference IDs have no separators (`RefId`). `Amount` colours only the +/− sign by Direction. Dates are Jalali via `Intl` `fa-IR`.
- Components in `src/js/components/` are `fn(props) → HTMLElement` built with `el()` from `src/js/dom.js`; form controls (`SearchInput`, `Dropdown`) return `{ field, control }`. Text goes through text nodes; `innerHTML` stays out of the codebase.
- Use `Dropdown` (`src/js/components/Dropdown.js`) for every select: `control.value` reads/writes like a select's, and `inline: true` puts the list in the flow (for use inside a `Dialog`). Modals use `Dialog` (native `<dialog>`, bottom sheet on phones).
- `src/styles/index.css` is the Tailwind input; design tokens live in its `@theme` (`bg-primary-900`, `text-success`, `rounded-md`, …). `src/styles/output.css` is generated but committed: rebuild it after class changes. Write full class names as string literals so Tailwind can find them.
- Mobile-first, `lg` is the desktop switch:
  - Results: transaction cards below `lg` (2 columns from `md`), a fixed-layout table at `lg`+.
  - Filters: inline dropdowns at `lg`+ apply at once; below `lg` they sit in a `Dialog` whose dropdowns hold a draft applied by its button.
  - Sort: table column headers at `lg`+, a sort `Dropdown` below.
- App state (search, filters, sort, page) is synced to the query string by `src/js/state.js`; invalid values fall back to defaults. Every change except paging resets to page 1; a page past the end clamps to the last page.
- Loading: the first load shows skeletons sized to a full page; later loads keep the current results dimmed via `aria-busy` (styled in `index.html`) and abort the previous request.
- `src/styles/fonts.css` is generated (`/* Generated by script */`). Leave it as generated.
